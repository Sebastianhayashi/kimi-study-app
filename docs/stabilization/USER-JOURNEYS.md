# 核心用户旅途

每条旅途必须从用户目标开始，以可验证的最终状态结束。只验证某个按钮能点击，不算旅途完成。

## J01 上传材料并进入生成界面

**目标：** 用户上传材料后，明确知道课程正在创建，而不是停在未知状态。

```text
打开书架
→ 选择支持的文件
→ 提交
→ 创建 courseId
→ 进入课程工作区
→ 显示生成动画、中文当前状态和进度
```

完成条件：

- 上传失败有明确错误并允许重试。
- 成功后不继续停留在上传弹窗。
- 生成中不显示空白课节。
- 当前状态和生成过程可访问。

## J02 课程生成完成、失败或中断

**目标：** 用户总能知道生成最终结果。

正常路径：

```text
understanding → generating → validating → ready
```

异常路径：

```text
generating → retrying → generating
generating → failed
generating → interrupted
```

完成条件：

- 进度不倒退。
- SSE 重复事件不重复展示。
- `ready` 后真实课节出现。
- `failed/interrupted` 后动画停止。
- 不出现永久空转。

## J03 浏览课程和切换课节

```text
进入课程
→ 打开 Lesson 1
→ 切换 Lesson 2
→ 返回 Lesson 1
```

完成条件：

- 中央课文、标题、目录 active、进度同步更新。
- 切换课节时旧阅读器、旧选区和旧 activity 状态不会污染新课。
- 左右侧栏状态符合产品约定。

## J04 查看原始材料并返回课程

```text
点击原文
→ 打开 PDF/EPUB/文本
→ 使用目录、搜索、翻页、缩放或字号
→ 关闭阅读器
→ 返回同一课节
```

完成条件：

- 文件成功渲染，或进入明确错误状态。
- 关闭后不刷新课节。
- 返回时 Lesson、课文滚动位置、Tutor 和笔记不丢失。
- 新窗口打开链接正确。

## J05 划词并向 Tutor 提问

```text
在 iframe 选中文字
→ 点击问助手
→ 父页面出现引用 Chip
→ 输入问题
→ 发送
→ 收到基于选区和上下文的回答
```

完成条件：

- 引用内容、章节和上下文准确。
- 移除引用后，不再发送旧 selection context。
- 切换课节后旧选区自动清理。
- malformed postMessage 不影响页面。

## J06 创建和管理笔记

```text
划词
→ 创建笔记
→ 编辑
→ 折叠/展开
→ 刷新页面
→ 笔记恢复
→ 删除
```

完成条件：

- 高亮锚点恢复到原文。
- 内容和左右位置持久化。
- 无笔记时课程不预留空白侧栏。
- 用户可以完全收起笔记。

## J07 完成互动练习

```text
看到活动
→ 错误回答
→ 查看反馈和提示
→ 重试
→ 正确回答
→ 刷新页面
```

完成条件：

- 题目规格合法时正常渲染。
- 错误题目规格显示明确降级，不出现一组重复红框。
- 反馈、提示、重试和 mastery 持久化。
- 正确答案不出现在公共 lesson HTML 或公共 API 中。

## J08 使用 Tutor 完成连续问答

```text
输入问题
→ 发送
→ 等待
→ 收到 Markdown 回答
→ 点击动态建议
→ 新对话
```

完成条件：

- 长表格、代码和链接不撑破右栏。
- 发送中状态清晰，不可重复提交。
- 失败可重试。
- 刷新后历史恢复。
- 新对话真正清除后端历史。

## J09 生成下一课

```text
点击下一课
→ 按钮进入等待
→ 中央生成覆盖层出现
→ 新课生成完成
→ 自动打开新课
```

完成条件：

- 当前已有任务时返回明确 busy 状态。
- 失败后按钮恢复。
- 成功只增加一节课。
- 新课 lesson 与 assessment 同时可用。
