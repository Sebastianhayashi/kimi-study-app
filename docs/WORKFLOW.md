# 用户工作流

## 1. 选择材料

用户可以从课程库进入上传流程，选择 PDF、EPUB、Markdown 或 UTF-8 文本。

系统应当：

- 检查扩展名、MIME、大小和文件可读性；
- 清理原始文件名中的路径成分；
- 在独立课程工作区中保存材料；
- 在检查失败时保留明确、可重试的失败记录。

## 2. 明确 Mission

生成课程前，系统使用材料检查结果和用户答案形成 Mission：

- 想掌握什么；
- 什么结果算学会；
- 有哪些时间、范围或难度约束；
- 哪些内容是重点；
- 用户已有怎样的基础。

未定义的关键产品行为不应由模型静默猜测。

## 3. 生成课程

课程生成状态机：

```text
idle
→ uploading
→ understanding
→ generating
→ validating
→ ready
```

异常路径：

```text
generating → retrying → generating
generating → failed
generating → interrupted
```

界面只保留一个工作流主进度条。页头和侧栏可以展示阶段摘要，但不得复制同一进度并出现不同数值。

## 4. 学习课节

课程工作区协调三个区域：

- 左侧：Mission、学习地图、目录、笔记和学习记录；
- 中间：当前互动课节、课节工具和原文入口；
- 右侧：绑定当前课程的 Kimi Tutor。

切换课节时必须清理旧选区、旧活动运行时和旧资源阅读器实例，但保留合法的课程级聊天、笔记和学习记录。

## 5. 互动与诊断

互动活动支持：

- 提交答案；
- 查看反馈；
- 请求提示；
- 重试；
- 记录独立证据和迁移证据；
- 将误区与概念掌握写入学习记录。

答案键和私有评估数据不得出现在公共课节 HTML 或通用文件 API 中。

## 6. 划词、笔记与 Tutor

用户选中课文后可以：

- 把选区发送给 Tutor；
- 创建锚定原文的笔记；
- 编辑、折叠、恢复或删除笔记。

Tutor 请求会组合当前课节、选区、Mission、笔记、掌握情况和误区。移除引用或切换课节后，旧 selection context 必须清理。

## 7. 生成下一课

下一课生成使用独立事务：

```text
preflight
→ 记录工作区基线
→ 启动同一课程的 Kimi session
→ 只允许新增一课及匹配评估
→ 验证文件与质量
→ 发布
```

验证失败时只清理当前运行新增的文件，不得修改或删除已发布课程内容。
