# 仓库整理调研

本次仓库整理参考了成熟开源产品和 Agent 项目的共同做法，但没有复制其品牌文案或产品实现。

## 参考模式

### SurfSense

可借鉴：

- README 首屏使用宽幅产品视觉；
- 先定义明确类别和用户问题，再进入安装；
- 通过 GIF 展示真实工作流；
- 同时提供云端、自托管、文档和社区入口；
- 对竞品类别进行直接、具体的比较。

应用到 Kimi Study：先展示“材料 → 课程 → 互动学习 → Tutor”的实际效果，再说明本地安装。

### OpenBookLM

可借鉴：

- 清楚定义目标用户、核心功能和系统架构；
- 提供产品截图、Demo、Issue 和 Feature Request 入口；
- 使用 Mermaid 解释服务关系；
- 把安装、贡献和许可证形成完整开源项目闭环。

应用到 Kimi Study：增加产品模型、架构、贡献、安全和 Issue 模板。

### NotebookLlaMa

可借鉴：

- 第一屏立即播放真实演示；
- 用极短的一句话说明与已知产品类别的关系；
- 把启动步骤写成可以逐条复制的命令；
- 对外部服务和 API Key 前置条件不做隐藏。

应用到 Kimi Study：明确 Kimi CLI 是真实生成的前置条件，同时提供无模型 Fixture 演示。

### 成熟工程仓库的共同点

1. 先展示结果，再解释技术；
2. Quick start 只有一条主路径；
3. Demo 与真实生产能力明确区分；
4. README 不承载所有细节，架构、质量和限制进入 docs；
5. 提供 CI、Issue 模板、贡献、安全和 Release 机制；
6. 用截图、测试和状态门禁支持主张，而不是只使用宣传语；
7. 已知限制公开，避免把研究原型包装成生产 SaaS。
